## 3–4. Backward traversal and complexity

**YES: path finding already uses dictionary/set lookup.** [`Traversal.from_seed():99–116`](/home/rajee/projects/cis695-agent-reliability/reports/callgraph_selection/phase2/callgraph_selector.py:99) uses:

```python
if seed in self.cache:
    return self.cache[seed]
shortest = {seed: Route((seed,), ())}
frontier = {seed: shortest[seed]}
# Three breadth-first layers:
for caller, edge in self.reverse.get(callee, ()):
    if caller in shortest:
        continue
```

This is **layered BFS**, not DFS or repeated full-edge scanning. Each layer collects a `following` dictionary; previously reached nodes are not expanded again. Equal-distance alternatives use a deterministic route-key tie-break; one shortest route is retained per reached node, not every possible path. Results are cached per seed. `test_paths()` intersects reached IDs with the test-definition set ([`:118`](/home/rajee/projects/cis695-agent-reliability/reports/callgraph_selection/phase2/callgraph_selector.py:118)). Only uniquely resolved changed-symbol seeds enter traversal ([`selectors:153–158`](/home/rajee/projects/cis695-agent-reliability/reports/callgraph_selection/phase2/run.py:153)).

Let `M` count admitted caller–target incidences, including multiple targets/call sites. Reverse-index construction costs roughly **O(E + M)**, plus per-edge target sorting/deduplication. A cold seed query costs **O(V_reached + M_examined)** within three hops, with average constant-time hash lookup and bounded-length route comparisons. A cached query returns its stored dictionary directly; subsequent test filtering still scans reached entries. Multiple seeds can revisit overlapping neighborhoods: total work is the sum of their BFS costs. The two variants build separate reverse indexes once, and depth/budget comparisons reuse paths ([`selectors:174–198`](/home/rajee/projects/cis695-agent-reliability/reports/callgraph_selection/phase2/run.py:174)). These are implementation-derived bounds, not timings.

The later side experiment likewise uses set-frontier BFS and reverse dictionary/set adjacency, not full-edge scans per hop: [`next_steps/freeze.py:215`, `reverse_reach()`](/home/rajee/projects/cis695-agent-reliability/reports/next_steps/freeze.py:215), [`graph_select():235`](/home/rajee/projects/cis695-agent-reliability/reports/next_steps/freeze.py:235). It is a separate multi-seed traversal, not the Phase-2 ranking implementation.

Constructor consequence: a changed `__init__` seed does **not** automatically reach callers of `MyClass(...)`; reaching the class node and reaching its initializer are different graph relationships.

**Exact status decision:** [`Graph.resolve_calls():146–162`](/home/rajee/projects/cis695-agent-reliability/reports/callgraph_selection/static_graph.py:146) deduplicates references and extracts node targets. One reference, one node target, no uncertainty → `resolved`, **unless** the target is decorated/conditional, which makes it `ambiguous`. Any remaining candidate node targets → `ambiguous`; no node target → `unresolved`. Thus **one candidate target can still be ambiguous**. Reasons retain the first uncertainty via `reason or …`, not an exhaustive causal explanation.

All decorators are conservatively marked custom; definitions under control-flow constructs are conditional ([`Indexer.definition:275`](/home/rajee/projects/cis695-agent-reliability/reports/callgraph_selection/static_graph.py:275), [`conditional_visit:380`](/home/rajee/projects/cis695-agent-reliability/reports/callgraph_selection/static_graph.py:380)). Lambda/comprehension/annotation calls are explicitly unsupported; attribute/import expansion has depth guards ([`unsupported_visit:394`](/home/rajee/projects/cis695-agent-reliability/reports/callgraph_selection/static_graph.py:394), [`Graph.resolve:165`](/home/rajee/projects/cis695-agent-reliability/reports/callgraph_selection/static_graph.py:165), [`expand_imports:237`](/home/rajee/projects/cis695-agent-reliability/reports/callgraph_selection/static_graph.py:237)). Assignments accumulate unknown bindings rather than performing flow-sensitive value propagation.

## 7–8. Ranked limitations and efficiency checks

The ranking below is an inference from code and stored diagnostic categories, **not measured causal attribution or profiling**.

1. **Weak/conservative call-target modeling:** missing receiver/value propagation, inherited-member resolution and detailed decorator/descriptor semantics. The recorded non-exact internal categories contain **1,759,990 definition/receiver cases**, **509,293 cases already having candidate targets**, **187,318 module-binding cases**, and **23,897 import-origin cases** ([`followup_summary.json:92–95`](/home/rajee/projects/cis695-agent-reliability/reports/callgraph_selection/followup_summary.json:92)). About 71% fall in the first broad bucket. These categories are not disjoint explanations such as “71% inheritance”; they establish namespace/target evidence without exact resolution.
2. **Python dynamic dispatch and framework indirection:** runtime subclasses, factories, callbacks, rebinding and custom attribute behavior exceed those static rules. Some uncertainty is warranted; some is recoverable with better modeling. Code alone cannot quantify that split.
3. **AST-model/resource coverage:** unsupported expression scopes, unavailable external definitions, parse failures and omitted files limit available evidence. The original four resource-limited graphs were excluded from 33.7%, so they cannot explain that rate as four zero-resolution tasks. Amended builds retain parsed ASTs and index without reparsing, but explicitly omit oversized retained input ([`AmendedGraph.build:88–137`](/home/rajee/projects/cis695-agent-reliability/reports/callgraph_selection/amended_graph.py:88)).
4. **Lookup/traversal performance:** secondary optimization opportunities exist, but no evidence identifies them as the main explanation for an exact-target percentage. Traversal happens **after** edge classifications have already been written.
