# Why the six recorded regression tests are unreachable

A practical static improvement can plausibly recover some real detecting identities, but there is no single receiver-inference fix for these six cases. The best small bounded opportunity is a pytest fixture-to-module adapter with a literal builtin-plugin lookup: **one of six tests**. The Q cases offer another **one or two tests**, but need several independent precision improvements, including a global attribute-mutation guard that blocks `deconstruct` even after imports and inheritance are addressed. These are source-supported design estimates, **not measured recoveries**. No fixes or counterfactual graph edges were implemented.

**Recommendation: do not pursue SCG as a V2 test-exclusion gate.** Further broad type propagation has diminishing returns here. If another research experiment is worthwhile, limit it first to the pytest fixture/plugin case and evaluate detecting-test reachability before considering integration. Preserve V2's existing candidate pool; SCG as auxiliary ranking evidence would need separate validation, particularly at finite prefixes. This diagnosis changes no production logic or experimental policy.

## Scope and evidence

The denominator is six named historical existing-suite regressions across five candidate patches, as recorded in [`group4_failing_tests.json`](../../../failure_analysis/group4_failing_tests.json) and [`group4_regression_rerun.json`](../../../failure_analysis/group4_regression_rerun.json). The latter reports cached baselines. These patches were oracle-resolved: detecting an existing-suite compatibility regression is not equivalent to identifying a wrong patch. The seven official existing-base failure witnesses from the previous audit are a different evidence tier and are excluded here.

Inspection starts at frozen experimental commit `b77056f`. Candidate patch bytes/source runs were matched to the frozen historical snapshots; archive SHA-256 and PAX base commit were verified. Existing graph artifacts and enhanced edge files were hash-verified. Candidate views below are in-memory unified-diff reconstructions with old-side context/hunk validation, used only for source inspection. Benchmark modules were never imported or executed.

All six test identities map uniquely to their base graph definitions. All existing edited targets map correctly; the forms patch additionally introduces two functions absent at base. Corrected B at ALL misses every test at depths 1, 2 and 3 in both edge variants. A **read-only, uncapped forward BFS on the stored edges** also finds no path to any corrected seed for any of these tests, including ambiguous edges. Thus these current misses are not merely ranking, finite-budget, or depth-truncation effects. This query does not change the frozen depth or selector. Absence from the stored graph is never treated as absence of runtime invocation.

## R01 — django-12209: inherited ORM save

- **Task/test:** `django__django-12209`, `tests/basic/tests.py::ModelInstanceCreationTests::test_save_primary_with_default` (line 137).
- **Edited function:** `django/db/models/base.py::Model._save_table` (base line 829). The patch removes the default-primary-key shortcut that forces an INSERT.
- **Source-backed expected invocation chain:** the test calls `PrimaryKeyWithDefault().save()` at line 140. `tests/basic/models.py:47` declares `PrimaryKeyWithDefault(models.Model)` without a save override. The inherited `Model.save` calls `self.save_base(...)` at `base.py:746`; `Model.save_base` calls `self._save_table(...)` at line 783. This is a three-call test-to-target chain. The constructor is a receiver-producing expression, not another sequential call hop to `_save_table`.
- **Exact first break:** the call site `tests/basic/tests.py:140:12`, expression `<Call>.save`, has no targets and reason `dynamic_receiver_or_callable`. The nested `PrimaryKeyWithDefault()` call at the same location resolves to its class; **class reachability does not imply method reachability**.
- **Additional breaks:** the two internal `self` calls already name their intended targets but are **ambiguous**, reason `uncertain_class_definition`, because `Model` has `metaclass=ModelBase` (`base.py:404`). Resolved-only traversal excludes them. Adding just the first edge would still not recover the primary path. The enhanced pass also rejects inherited/custom-creation classes.
- **Classification/fixability:** constructor-expression receiver, inherited method lookup, and metaclass uncertainty. A bounded may-call analysis could trace the declared hierarchy and three calls; accepting them as uniquely resolved requires a justified `ModelBase`/mutation model. Runtime information can verify the concrete dispatch but is not intrinsically necessary for a conservative candidate path. **One possible recovery**, conditional on all these features, not credited to a simple constructor fix. Complete graph; no omission explains this miss.

The query-count assertion is consistent with the removed INSERT shortcut causing an extra UPDATE attempt. That is a source explanation of the historical failure, not a newly executed SQL trace.

## R02 — django-14140: direct Q receiver

- **Task/test:** `django__django-14140`, `tests/queries/test_q.py::QTests::test_deconstruct` (line 38).
- **Edited function:** `django/db/models/query_utils.py::Q.deconstruct` (line 83). The patch moves a single child's key/value from `kwargs` into positional `args`; the test explicitly expects empty args and that key/value in kwargs.
- **Expected call/data path:** test line 39 assigns `q = Q(price__gt=F(...))`; line 40 directly invokes `q.deconstruct()`. `Q.deconstruct` is declared on Q itself: no inherited `deconstruct` lookup is needed. The receiver's constructor class nevertheless inherits `tree.Node`.
- **Exact first invocation break:** `tests/queries/test_q.py:40:29`, `q.deconstruct`, is unresolved with no targets, reason `uncertain_or_rebound_name`.
- **Earlier receiver-evidence barrier:** the test's `from django.db.models import Q` is at line 1. That package explicitly reexports Q at `django/db/models/__init__.py:28`, after its star imports. The frozen test-module binding contains both the exact Q class and `unknown:star_import_may_bind_attribute`; consequently the constructor call at test line 39 is ambiguous. The resolver applies a whole-module star-import flag rather than statement-order reasoning. This is a specific import-model imprecision, not evidence that Q is actually rebound here.
- **Why the type pass stops:** `constructor()` rejects the uncertain import result. Even after fixing that, `safe_class()` rejects every class with bases, including `Q(tree.Node)`. Q and Node have source-inspectable definitions without their own `__new__`, `__getattr__` or `__getattribute__`; bounded hierarchy checks offer a narrower route than globally trusting inheritance.
- **A further independent guard:** the pass records attribute mutation by **name across the whole indexed project**. `django/db/models/deletion.py:54` assigns `set_on_delete.deconstruct`, and `django/utils/deconstruct.py:49` assigns `klass.deconstruct`. Both source files are indexed. `resolve_calls()` requires the method name to be absent from this global set, so fixing imports and class eligibility still cannot add Q's edge. Q itself is not decorated by `deconstructible` in its declaration. A receiver-sensitive mutation analysis would have to distinguish these writes without ignoring unknown mutations.
- **Classification/fixability:** reexport/star-import overtaint plus local receiver propagation, an overly broad inheritance exclusion, and global attribute-name mutation overtaint. **Bounded static candidate recovery is well supported: one direct call, within every frozen depth.** No fixture/runtime-generated callable is needed. Preserving uncertainty around external mutation remains necessary. Complete graph and correct changed-method mapping.

The older secondary selection hit this test by its ambiguous **constructor-to-Q-class** edge. The old mapper seeded the container Q from hunk text; corrected mapping keeps the edited `Q.deconstruct` method and removes Q as a seed. Restoring the container seed would not demonstrate a method invocation path. The frozen `qualified_mapping/old_resolved_target_audit.csv` explicitly records this exclusion.

## R03 — django-14140: negated Q receiver

- **Task/test:** `django__django-14140`, `tests/queries/test_q.py::QTests::test_deconstruct_negated` (line 45).
- **Edited function:** the same `Q.deconstruct` at `query_utils.py:83`.
- **Expected call/data path:** line 46 binds `q = ~Q(...)`, then line 47 invokes `q.deconstruct()`. This needs a **different receiver fact** from R02. `Q.__invert__` (`query_utils.py:67–71`) constructs `obj = type(self)()`, negates it and returns `obj`. Given the direct operand's Q class, the method body supports a Q-valued result under the ordinary construction assumptions. The unary operation happens before the direct deconstruct call; it is not a call from `__invert__` into `deconstruct`.
- **Exact first break:** the `~Q(...)` result has no inferred type. The indexer records explicit `ast.Call` sites, not the implicit `__invert__` invocation; `value_expr()` classifies `UnaryOp` as unknown. At `tests/queries/test_q.py:47:29`, `q.deconstruct` is unresolved with no targets (`uncertain_or_rebound_name`). The Q constructor at line 46 also has R02's imported unknown binding.
- **Classification/fixability:** implicit unary dispatch and method-return/`type(self)()` inference, **in addition to** the import/hierarchy/global-mutation barriers in R02. A bounded receiver-conditioned summary of this source body can supply a may-call target without runtime tracing. Fixing R02's imports/local constructors alone does **not** recover this test. **One additional potential recovery**, contingent on the separate return summary; no implemented gain is claimed. Complete graph.

The older secondary hit was again the Q-class constructor seed, not an operator/return-to-deconstruct path. Both Q tests must therefore remain separate recovery estimates.

## R04 — django-14631: property-triggered cleaning

- **Task/test:** `django__django-14631`, `tests/forms_tests/tests/test_forms.py::FormsTestCase::test_datetime_clean_initial_callable_disabled` (line 2115).
- **Edited functions:** existing `BaseForm._clean_fields` (`django/forms/forms.py:389`) and cached-property `BaseForm.changed_data` (line 438); new `BaseForm._bound_items` and `BoundField._did_change` exist only in the candidate.

Inherited `BaseForm.errors` is a property (`forms.py:170–175`): `_errors` starts as None and the getter calls `self.full_clean()` at line 174. `full_clean()` calls `_clean_fields()` at line 385. No `changed_data` path is required to explain this test.
- **Exact first missing invocation edge:** `form.errors` at test line 2122 → `BaseForm.errors`. **There is no call-site edge record at all for that attribute load**, because the graph indexes explicit calls. The nested DateTimeForm constructor itself resolves to its class, which does not model the getter invocation.

Candidate `_clean_fields` reads `bf.initial`; `BoundField.initial` (`boundfield.py:213–220`) removes microseconds for widgets that do not support them, whereas the old disabled-field branch calls `get_initial_for_field` directly. This explains the assertion expecting the original datetime with microseconds.
- **Classification/fixability:** descriptor invocation absent from the graph, plus inherited/metaclass/decorator dispatch. Bounded property and hierarchy summaries could recover one test at depth 3; resolving only candidate-new definitions would not. Runtime values determine whether the getter cleans on an arbitrary access, but this source exposes its initial state; a may-call getter edge does not require runtime. Partial graph has only an unrelated intentionally invalid test file, `tests/test_runner_apps/tagged/tests_syntax_error.py`; the relevant files/nodes are present.

Overlapping barriers: inheritance/custom class handling affects R01–R04 and R06; Q import and global mutation overtaint affect R02–R03; fixture typing affects R05–R06. R06 also demonstrates an incorrectly narrow **resolved** edge, so simply reducing unresolved counts is an inadequate success metric. Zero primary cases are explained by missing test identity, an incorrectly mapped existing edited target, parse/quota omission, or finite selection budget. Candidate-only functions occur in R04 but are not necessary to its route to an existing changed body.

## Best bounded next experiment and expected payoff

Prefer **fixture-to-module value flow with a narrowly scoped literal builtin-plugin registry summary** (R05). Resolve the class-local fixture by pytest scope rules, follow its returned module value under the visible default-plugin registration, and use that value for the test's existing explicit call. Keep uncertain/overridden fixtures and registry bindings uncertain. If the adapter can establish only an ambiguous module target, resolved-only B still recovers zero; the one-test estimate is conditional on justifying the existing resolved-edge criterion. This is a framework adapter rather than a generic class-type change. It has a concrete one-edge test-to-target endpoint and avoids changing traversal depth or treating fixture setup as an invented invocation chain.

The more general Q alternative needs **all** of: statement-order-aware explicit reexports; constructor receiver facts for a class with an inspected base hierarchy; and receiver-sensitive attribute mutation facts replacing the global `deconstruct` veto. R03 additionally needs unary/return inference. The presence of `obj.__class__` mutation in the separate Node factory is another reason to inspect constructor-relevant behavior rather than globally allow inherited classes. No one of these features alone is sufficient. Preserve provenance, bound hierarchy/flow exploration, and fail uncertain cases closed; do not drop safety guards or restore container-class seeds.
| Proposed work, not implemented | Source-supported potential recovery among these six | Main risk |
|---|---:|---|
| Only fix imports, or only relax inheritance | 0 | Other guards, including global mutation, still block Q |
| Import order + constructor receiver + verified hierarchy + receiver-sensitive mutation | **1 (R02)** | Several interacting analyses; import cycles, base behavior, unknown class/member mutation |
| Above plus bounded `__invert__`/`type(self)()` return summary | **2 total (R02–R03)** | Unsound return-type inference, custom creation, implicit operator semantics |
| **Recommended: fixture-to-builtin-module adapter** | **1 (R05)** | Fixture scope/overrides, plugin blocking/re-registration, registry state absent from graph |
| ORM metaclass/receiver summaries | Up to 1 more (R01), three-call path | Must resolve both internal ambiguous calls; Django-specific complexity |
| Property + forms class/decorator summaries | Up to 1 more (R04), three-call path | Descriptor shadowing/cache state, metaclass/decorator effects; new helpers alone do not help |
| Sphinx framework/visitor/dependency modeling | **0 credited at depth 3** | Long pipeline, extension overrides, external source gaps, shortcut edges change meaning |

**Measured improvement from this diagnosis: zero, because no change was made.** The recommended pytest experiment has a one-test source-supported target (16.7% of the six). The independent Q bundle offers one further test; adding its operator/return extension offers another (three combined, 50%). Each is a separate feature commitment, not an automatic gain from type propagation. These are post-hoc targets on a tiny known set, not predicted population recall, timing results or implementation guarantees. Recovered identities must be demonstrated under the unchanged selector/depth/budget, with independent false-edge audits and finite-prefix witness retention checks. A broad static may-call path is not proof that a test executes the changed body on every input.

This evidence does **not** establish an unavoidable runtime wall for all six. It establishes that the remaining work is fragmented semantic/framework modeling, and one expensive case still conflicts with the frozen depth. The existing type-propagation and qualified-mapping gains did not produce detecting-test recall. That makes further investment hard to justify for V2 gating; a small, separately evaluated fixture/plugin experiment is defensible as research, with a stop condition if it cannot recover its direct witness without unsafe certainty or large selection growth.
